Improving Address Matching Using Siamese Transformer Networks

We present a Siamese Transformer system for large-scale address matching, combining a fast bi-encoder retriever with a precise cross-encoder reranker to achieve over 95% door-level accuracy and 4.5× faster inference than traditional methods.

Introduction

Unstructured postal addresses rarely follow a consistent template. The same physical location may appear with missing fields, reordered components, typos, or redundant descriptors. Traditional approaches such as edit distance, token sorting, and rule-based normalization are fast but brittle because they operate only on surface text. They struggle when two visually different address strings refer to the same real-world doorstep, and as national-scale databases grow, comparison becomes slow and increasingly inaccurate.

So how do we capture an address's semantic meaning while keeping matching practical at postal scale?

The Key Idea

Treat address matching as a two-stage semantic retrieval problem. First, embed every normalized address into a dense vector space using a Siamese bi-encoder. When a new unnormalized address arrives, embed it once and retrieve the top 10 most similar candidates using cosine similarity.

Then apply a cross-encoder to those candidates for deep pairwise comparison, allowing the model to rerank them and identify the true match with high precision.

This design works because:

  • Low false negatives during retrieval. The bi-encoder retrieves the correct address in the top 10 for 99.41 percent of cases, even when the input is noisy or unstructured.
  • High precision when a match exists. The cross-encoder captures fine structural details such as artery type, house number, floor information, and ZIP code, enabling door-level accuracy above 95 percent.

In practice, combining postal code prefix filtering with confidence-based thresholds provides a strong balance. Retrieval offers high recall, reranking delivers high precision, and the overall system runs four to five times faster than BM25 when using GPU inference.

The BI+CE Address Matching Model

The BI+CE architecture approaches postal address matching as a two-stage semantic similarity task. Instead of relying on symbolic string metrics, the system retrieves likely candidates using dense embeddings and then performs deep pairwise reasoning to determine which normalized address truly corresponds to the provided unnormalized input. This results in highly accurate retrieval even when the original address is noisy, incomplete, or formatted inconsistently.

1) Normalized Address Pre-Embedding

Before processing any real-world queries, the system embeds every normalized Portuguese address in the database. Each address is passed through a bi-encoder to produce a fixed-length vector representation. This produces a static embedding index that enables fast cosine-similarity retrieval.

Example: Each normalized postal record is transformed into:

ID_001: 512-dim embedding of “Rua das Flores 12, 1200-045 Lisboa”
ID_002: 512-dim embedding of “Avenida do Mar 58, 9000-206 Funchal”
ID_003: 512-dim embedding of “Travessa Azul 3, 4000-281 Porto”

These vectors form the searchable embedding database.

Figure 2: Interactive bi-encoder architecture.

2) ZIP-Based Filtering for Efficient Retrieval

To reduce search space and accelerate inference, embeddings are partitioned into nine auxiliary groups according to the first digit of the CP4 postal code. When a new query arrives, only the relevant group is scanned. This preserves efficiency without reducing recall.

Example: A query with CP4 starting in 1 is compared only against:

Group_1 → All normalized addresses whose CP4 begins with “1”
Group_2 is ignored, Group_3 is ignored, …

This reduces unnecessary comparisons and increases throughput.

3) Bi-Encoder Retrieval

When an unnormalized address is provided, it is embedded using the same bi-encoder. The embedding is then compared against the filtered group using cosine similarity, producing the top-k most similar candidates. The system uses k = 10, which was found to reliably include the correct address in nearly all cases.

The correct normalized address usually appears within this list.

4) Cross-Encoder Reranking

Each of the top-10 candidate pairs is then passed through a cross-encoder. Both addresses are fed jointly as a sentence pair, allowing the transformer to evaluate their semantic relationship in detail. The cross-encoder outputs a matching probability for every candidate.

Choosing the matching probability threshold

After reranking, the system applies a threshold to determine which predictions can be safely automated. Evaluations show that a cutoff at 0.90 maximizes operational reliability, retaining nearly all correct predictions while ensuring ambiguous cases are routed for manual review.

The histogram below illustrates why this threshold works so well. The bi-encoder (left) concentrates nearly all predictions at very high probability, making it difficult to distinguish confident from uncertain matches. In contrast, the BI+CE model (right) creates clear separation: low-confidence predictions cluster near 0, while high-confidence predictions cluster near 1, enabling effective automated filtering at τ = 0.90.

Why this works

The bi-encoder provides fast, scalable retrieval by capturing coarse semantic similarity, while the cross-encoder provides deeper contextual reasoning necessary for final disambiguation. Together, they deliver high precision and robustness, even when unnormalized addresses contain typos, missing fields, or nonstandard formatting.

Performance at Operational Granularity

With thresholding applied, door-level accuracy reaches 98.35%, and artery-level accuracy rises to 99.71%. Only about 18% of addresses require manual intervention, representing a substantial improvement over traditional string-based methods.

Key Results: Fast, high-accuracy Portuguese address matching

We evaluate our proposed BI+CE pipeline (bi-encoder retriever + cross-encoder reranker) against traditional string matching and strong neural baselines. Performance is measured on a held-out test set using artery-level and door-level accuracy plus inference speed.

Accuracy: BI+CE is near-perfect after confidence filtering

Without filtering, BI+CE matches doors correctly about as often as the bi-encoder alone, but it produces a much cleaner confidence separation. By accepting only predictions with matching probability > 0.90, BI+CE reaches 98.35% door-level and 99.71% artery-level accuracy while discarding only ~18% for manual review.

Stability across runs

Fine-tuning is consistent: over five runs, BI+CE shows a door-level standard deviation of only 0.084, indicating reliable training behavior.

Overall, BI+CE offers a strong operating point for real delivery workflows: high precision at the door level, a clean confidence threshold for routing uncertain cases to humans, and GPU-friendly inference that is several times faster than traditional BM25-style retrieval.

Conclusion

This work demonstrates that Siamese Transformer Networks provide an effective solution for large-scale address matching. By combining a fast bi-encoder for candidate retrieval with a precise cross-encoder for reranking, the proposed BI+CE system achieves over 95% door-level accuracy while maintaining practical inference speeds.

The two-stage retrieval approach proves particularly powerful: the bi-encoder successfully retrieves the correct address in the top-10 candidates for 99.41% of queries, while the cross-encoder refines these results with fine-grained semantic understanding. When combined with confidence-based thresholds (τ = 0.90), the system reaches 98.35% door-level accuracy and 99.71% artery-level accuracy, with uncertain cases flagged for human review.

Compared to traditional string matching methods like Token Sort and Token Set, which achieve only 17-27% door-level accuracy, and even strong neural baselines like DPR (85.91%), the BI+CE system offers substantial improvements. Furthermore, the use of ZIP-code-based filtering enables the system to run 4.5× faster than BM25-based approaches when using GPU inference.

As postal services and logistics companies continue to handle growing volumes of unstructured address data, semantic address matching becomes increasingly critical. The BI+CE architecture offers a practical, scalable solution that balances accuracy, speed, and the ability to defer uncertain cases to human operators—making it well-suited for real-world deployment in address normalization pipelines.
